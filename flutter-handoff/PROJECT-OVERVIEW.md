# شرح مشروع "سويق" — نظام مدرسة تعليم قيادة

ملف تعريفي كامل للمطوّر (ولأداة الذكاء الاصطناعي التي يستخدمها) لفهم المشروع من الصفر قبل بناء تطبيق الموبايل بـ Flutter.
يُقرأ مع `API.md` (المرجع التقني لكل المسارات). المشروع يعمل فعليًا: الباك اند + تطبيق ويب كامل، والمطلوب الآن تطبيق موبايل يستهلك **نفس الـ API بدون تعديل** (تعديلات صغيرة على الباك اند ممكنة عند الحاجة، انظر القسم 9).

---

## 1. ما هو المشروع؟

تطبيق لإدارة مدرسة تعليم قيادة سيارات. ثلاثة محاور:
1. **الحجوزات والجدولة**: الطالب يطلب درسًا، والمشرف يعيّن المدرب المناسب، والمدرب يعطي الدرس.
2. **محتوى تعليمي**: فيديوهات/صور بفئات، وكويزات مرتبطة بها، مع قفل تسلسلي اختياري.
3. **تتبّع تقدم الطالب** بالمهارات العملية (منجزة/غير منجزة) وأهلية شهادة الإتمام.

إضافةً: الدفع اليدوي (نقدًا / شام كاش) بتأكيد المشرف، رسائل بين الطالب والمشرف، إشعارات داخل التطبيق، لوحات إحصائية.
الاسم التجاري: **سويق**. اللغة: **العربية، واجهة RTL**. العملة المعروضة بالدولار (`$`).

### مكوّنات المشروع

| المكوّن | التقنية | الحالة |
|---|---|---|
| `backend/` | Laravel 12 + PHP 8.2 + Sanctum + SQLite (قابلة للتغيير) | **جاهز** ومغطى بـ 46 اختبار آلي |
| `my-react-app/` | React 19 + Vite + React Router | **جاهز**، يغطي كل الأدوار — مرجع عملي لكل الشاشات |
| تطبيق الموبايل | **Flutter** | **المطلوب الآن** |

الباك اند **API فقط** (بدون Blade). لا يوجد أي منطق عمل في تطبيق الويب: كل القواعد في الباك اند، فلا تكرّرها في Flutter إلا للتحقق الشكلي.

## 2. الأدوار (Roles)

كل مستخدم له دور واحد بالضبط (`users.role`):

| الدور | الوصف والصلاحيات |
|---|---|
| **admin (أدمن)** | يملك النظام: إحصائيات عامة، إنشاء/حذف المدربين والمشرفين، إدارة قائمة المهارات، الإعدادات العامة (سعر الدرس، مدة السماح للإلغاء، نسبة الغرامة، حساب شام كاش)، رفع المحتوى. لديه كل صلاحيات المشرف أيضًا. |
| **supervisor (مشرف)** | يدير التشغيل اليومي: يعتمد/يرفض أوقات توفر المدربين، **يعيّن المدرب** لطلبات حجز الطلاب، ينفّذ الإلغاء (حتى نيابةً عن المدرب)، يؤكد الدفعات يدويًا، يرد على رسائل الطلاب، يرفع محتوى وكويزات. |
| **instructor (مدرب)** | يقترح أوقات توفره (تحتاج اعتماد المشرف)، يرى جدول دروس اليوم وطلابه، يُنهي الدرس، **يقيّم مهارات طلابه**، يرى أهلية الشهادة. **لا** يراسل الطلاب ولا يلغي مباشرة (يطلب من المشرف). |
| **student (طالب)** | يسجّل حسابه بنفسه، يطلب حجزًا، يلغي حجزه، يسجّل دفعة، يشاهد المحتوى ويحل الكويزات، يتابع مهاراته، يراسل المشرف. |

الحسابات: **الطالب** يسجّل نفسه (`POST /register`). **المدرب والمشرف** ينشئهم الأدمن فقط. الأدمن الأول يأتي من الـ seeder.

## 3. قواعد العمل الأساسية (Business Rules)

### 3.1 دورة حياة وقت التوفر (AvailabilitySlot)
```
المدرب يقترح → proposed → المشرف يراجع → approved  (يصير قابلًا للحجز)
                                       → rejected  (مع سبب يظهر للمدرب)
```
المدرب لا يفرض أي وقت مباشرة. الموافقة أو الرفض تُرسل إشعارًا للمدرب.

### 3.2 دورة حياة الحجز (Booking)
```
الطالب يطلب حجزًا على وقت معتمد     →  pending
المشرف يعيّن (assign) وقتًا/مدربًا   →  confirmed   (إشعار للطالب)
المدرب/المشرف ينهي الدرس            →  completed
الطالب/المشرف يلغي                  →  cancelled    (قد تترتب غرامة)
```
- **الطالب لا يختار المدرب.** يختار وقتًا من المتاح، والمشرف هو من يقرّر التعيين النهائي (وقد يبدّل الوقت لوقت آخر معتمد).
- **نوع الغيار**: كل طالب يحدد `manual` أو `automatic` **مرة واحدة عند التسجيل** ولا يتغيّر. كل مدرب يدعم نوعًا أو كليهما (`teaches_manual`, `teaches_automatic`). التعيين **يُرفض** إذا كان المدرب لا يدعم نوع غيار الطالب. والقائمة `available` تُفلتر تلقائيًا بنوع الغيار.
- **السعر**: ثابت للجميع، مخزّن في الإعدادات (`lesson_price`)، و**كل حجز يحفظ نسخة من السعر وقت إنشائه** (`price`) فلا يتغيّر بتغيّر الإعداد لاحقًا.
- **الإلغاء والغرامة**: مدة سماح `cancellation_grace_hours` (افتراضي 24). إلغاء **قبل** (بداية الدرس − مدة السماح) = بلا غرامة؛ **بعدها** = غرامة `cancellation_penalty_percent`% من سعر الدرس (افتراضي 50%، أي نصف السعر). المدرب لا يلغي مباشرة بل يطلب من المشرف.

### 3.3 الدفع (يدوي بالكامل في v1)
- الطالب (أو المشرف) يسجّل دفعة على حجز بطريقة `cash` أو `sham_cash` → تُنشأ بحالة `pending`.
- **شام كاش**: لا يوجد تكامل API حقيقي. التطبيق يولّد رابطًا (`shamcash://pay?account=...`) يفتح تطبيق شام كاش على حساب المدرسة (الحساب يضبطه الأدمن في الإعدادات). استلام المال يؤكده المشرف/الأدمن يدويًا (`confirm`) فتصير `confirmed` ويُشعَر الطالب.

### 3.4 المحتوى التعليمي
- **فئات ديناميكية** يضيفها المشرف/الأدمن (نظري، إشارات، قطع السيارة...). كل فئة لها `is_sequential`.
- فئة **متسلسلة**: المحتوى يُشاهَد بالترتيب (`order_index`)، ولا يفتح العنصر التالي حتى يشاهد الطالب السابق **وينجح بكويزه** (إن وُجد). فئة **غير متسلسلة**: تصفّح حر والكويز للمراجعة فقط.
- الكويز اختياري لكل محتوى؛ **المحاولات غير محدودة**؛ علامة النجاح `pass_score` (٪). إجابات الكويز الصحيحة **لا تُرسل للطالب أبدًا** (التصحيح يتم على السيرفر).
- الطالب يؤشّر المحتوى "شاهدته" بزر صريح (`POST /contents/{id}/view`).

### 3.5 المهارات العملية
- قائمة المهارات (ركن متوازي، طريق سريع...) يديرها الأدمن.
- التقييم **ثنائي** (منجزة/غير منجزة)، يحدّثه **المدرب** متى شاء، **مستقل عن الحجوزات**.
- **شهادة الإتمام**: مؤهَّل الطالب عندما تكون كل المهارات منجزة (استعلام `certificate-eligibility`).

### 3.6 الرسائل والإشعارات
- **دردشة حرة بين الطالب والمشرف/الأدمن فقط.** لا تواصل طالب↔مدرب داخل التطبيق إطلاقًا.
- الإشعارات (تأكيد حجز، إلغاء، تذكير قبل 24 ساعة، اعتماد/رفض وقت، تأكيد دفع) تُخزَّن في الداتابيس وتُرسل بإيميل، وتُقرأ عبر `GET /notifications`. **لا Push حقيقي في v1** (مؤجَّل لـ v2 عبر Firebase حسب الخطة الأصلية).

## 6. تطبيق الويب كمرجع للشاشات (`my-react-app/`)

نفس الـ API الذي سيستهلكه Flutter. كل صفحة في `src/pages/` مثال حي لتدفق شاشة كاملة، وكل ملف في `src/api/` يوضح كيف تُستدعى المسارات وكيف تُحوَّل الحقول. دليل تقني بالعربية في `my-react-app/REACT-GUIDE.md`.

### خريطة الشاشات لكل دور
| الشاشة (مسار الويب) | الدور | المسارات المستخدمة |
|---|---|---|
| تسجيل الدخول `/` | الجميع | `POST /login` |
| إنشاء حساب `/register` | طالب | `POST /register` |

| حجز درس `/student/booking` | ST | `GET /availability-slots/available?transmission_type=`, `POST /bookings` |
| المحتوى `/student/content` | ST | `/content-categories` + `/me/content-progress` (تُدمج محليًا) + `/contents/{id}/view` |
| الكويز `/student/content/:id/quiz` | ST | `GET /contents/{id}`, `POST /quizzes/{id}/submit` |
| مهاراتي `/student/skills` | ST | `/me/skills` (+ `/skills`) |
| راسل المشرف `/student/messages` | ST | `/messages/with/{id}`, `POST /messages` |
| لوحة المدرب `/instructor` | I | `/dashboard/instructor`, `POST /bookings/{id}/complete` |
| طلابي `/instructor/students` | I | `GET /instructor/students` |
| تقييم مهارات طالب `/instructor/students/:id/skills` | I | `/students/{id}/skills`, `PUT /students/{id}/skills/{skillId}`, `certificate-eligibility` |
| أوقات توفري `/instructor/availability` | I | `/availability-slots/mine`, `POST /availability-slots` |
| الشاشة اليومية `/supervisor` | S | `/dashboard/supervisor`, approve/reject، `assign`، `confirm` دفعة، `cancel` |

**نطاق تطبيق الموبايل** (أي الأدوار ستُبنى أولًا) قرار لصاحب المشروع؛ الـ API يدعم كل الأدوار. الترتيب المنطقي عادةً: **طالب** ثم **مدرب**، ثم مشرف/أدمن إن لزم.

### الهوية البصرية (اختيارية للتطابق مع الويب)
خلفية بيضاء مسطّحة `#f6f6f4`، سطوح بيضاء بحدود رفيعة، **لون رئيسي واحد فقط** أخضر غابي غامق `#2f4d3c` للفعل الأساسي وحالة "منجز"، والأزرار الثانوية (رفض/خروج/إلغاء) رمادية محايدة بدون ألوان تحذير. بدون تدرجات أو توهّج. خطوط: `Noto Kufi Arabic` (عناوين) و`IBM Plex Sans Arabic` (نصوص). الأيقونات خطية بسيطة.

## 7. توصيات لتطبيق Flutter (اقتراحات وليست إلزامًا)

- **HTTP**: `dio` مع Interceptor للتوكن ومعالجة الأخطاء (انظر `API.md` قسم 6).
- **التخزين الآمن للتوكن**: `flutter_secure_storage`.
- **إدارة الحالة/التنقل**: اختيار المطوّر (Riverpod/Bloc + go_router مناسبان). فصل الطبقات: `data` (api+models) / `domain` / `presentation`، وتنظيم بحسب الميزة (auth, booking, content, skills, chat, notifications).
- **التوجيه بعد الدخول** حسب `user.role`.
- **الحالات**: كل شاشة تحتاج حالات: تحميل / خطأ (رسالة `message` من السيرفر) / فارغ / بيانات.
- **Polling** بدل الـ realtime: للرسائل والإشعارات (مثلًا كل 20–30 ثانية عند فتح الشاشة).
- **RTL**: `Directionality`/`locale: ar`، وخط عربي.
- **الأموال** نصوص من السيرفر: حوّلها لـ `double` أو `Decimal` قبل الحساب.

## 8. قرارات ثابتة (لا تُغيَّر بدون سؤال صاحب المشروع)

1. تسجيل الدخول **بالهاتف** وليس البريد؛ البريد اختياري للإشعارات فقط.
2. الطالب **لا يختار المدرب**؛ المشرف هو من يعيّن.
3. نوع الغيار يُحدَّد **مرة واحدة** عند التسجيل.
4. **لا تواصل** مباشر بين الطالب والمدرب.
5. الدفع **يدوي** (نقدًا/شام كاش) وتأكيده من المشرف/الأدمن.
6. المدرب **لا يلغي** الحجز مباشرة.
7. التقييم بالمهارات **ثنائي** ومستقل عن الحجوزات.
8. سعر الحجز **لقطة** لا تتأثر بتغيير الإعدادات لاحقًا.

## 9. فجوات معروفة / أشياء قد تحتاج تعديلًا صغيرًا بالباك اند

| الموضوع | التفصيل | الاقتراح |
|---|---|---|
| لا `GET /dashboard/student` | شاشة الطالب الرئيسية تُركَّب من 3 طلبات | مقبول، أو يُضاف endpoint مجمّع |
| `GET /me/skills` يرجع فقط المهارات التي قيّمها المدرب | الطالب الجديد يرى قائمة فارغة | دمج مع `GET /skills` محليًا، أو تعديل الباك اند ليرجع كل المهارات |
| لا endpoint لمعرفة "من هو المشرف" للطالب | الرسائل تحتاج `receiver_id` | استخدام `id` معروف (v1 مشرف واحد) أو إضافة endpoint |
| رفع الملفات | المحتوى يُضاف كـ **رابط URL نصي** فقط، لا رفع فعلي (المخطط: Cloudinary لاحقًا) | مؤجَّل |
| Push Notifications | غير موجودة | v2 عبر Firebase (يحتاج تنسيقًا مع الباك اند: تخزين FCM token) |
| تكرار الدفعات | لا يمنع الباك اند تسجيل أكثر من دفعة لنفس الحجز | معالجة في الواجهة حاليًا |
| التوكن لا ينتهي | لا expiration مضبوط | ضبط expiration/refresh قبل النشر |
| CORS مفتوح `*` | مناسب للتطوير فقط | تقييده قبل النشر (لا يؤثر على الموبايل) |
| لا حماية من brute-force على الدخول | لا rate limiting مخصص | إضافته قبل النشر |
| رسائل التحقق بالإنجليزية | `errors.<field>` بالإنجليزي | ترجمة محلية بالعميل أو تعريب الباك اند |
| "اليوم" بتوقيت UTC | حدود اليوم في لوحات المدرب/المشرف بتوقيت السيرفر | ضبط `APP_TIMEZONE` بالباك اند لتوقيت سوريا إن لزم |
| Reminder المجدول | `bookings:send-reminders` كل ساعة يحتاج `php artisan schedule:work` أو cron | تشغيله بالإنتاج |

## 10. مسرد مصطلحات

| المصطلح | المعنى |
|---|---|
| وقت توفر (slot) | فترة زمنية يقترحها المدرب ليُحجز فيها |
| تعيين (assign) | اختيار المشرف للمدرب/الوقت النهائي لحجز الطالب |
| غيار عادي / أوتوماتيك | `manual` / `automatic` |
| تسلسل إجباري | `is_sequential`: المحتوى يُفتح بالترتيب بعد نجاح الكويز السابق |
| شام كاش | وسيلة دفع محلية؛ يدوية التأكيد في v1 |
| مدة السماح | ساعات قبل الدرس يُلغى فيها الحجز بلا غرامة |
| شهادة الإتمام | أهلية الطالب عند إنجاز كل المهارات |

## 11. للمطوّر: كيف تستخدم هذه الملفات مع أداة الذكاء الاصطناعي

أعطِ الأداة الملفات الثلاثة (`PROJECT-OVERVIEW.md` + `API.md` + `postman_collection.json`) ثم ابدأ بطلب مثل:

> "هذا مشروع نظام مدرسة قيادة. اقرأ `PROJECT-OVERVIEW.md` و`API.md` بالكامل. أريد تطبيق Flutter يستهلك هذا الـ API. ابدأ بطبقة الشبكة (Dio + interceptor)، ثم نماذج Dart لكل كائن في القسم 3 من `API.md` (مع مراعاة أن الحقول المتداخلة nullable وأن بعض الردود بدون غلاف `data`)، ثم شاشة تسجيل الدخول بالهاتف مع تحويل المستخدم حسب دوره."

اطلب منها بناء **ميزة واحدة كاملة كل مرة** (دخول → حجز → محتوى → مهارات → رسائل → إشعارات) وتجربتها على حسابات الاختبار قبل الانتقال للتالية. وعند أي تعارض بين هذه الملفات والسلوك الفعلي للسيرفر، **السيرفر هو المرجع** — أخبر صاحب المشروع لنصحّح التوثيق.
